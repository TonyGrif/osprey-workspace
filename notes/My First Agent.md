This is the starter "hello world" of Osprey with one MCP server for illustration.
# Configuration
This is handled through `config.yaml` and defines the project configuration. It connects to a mock connector and sets up saftey conditions.
# MCP Server Discovery
This is handled through `.mcp.json` and is auto generated by osprey build based on the servers included in `config.yaml`.
# Claude
Standard instruction format that Osprey agent reads on startup in `CLAUDE.md`. It should be used to define how agents behave, safety rules, and how to format responses.
# Usage
From the project directory, use `osprey claude chat` to start up a Claude code session. Standard `claude` command can work too, but it will ignore the `config.yaml` configuration for the configured LLM provider.
## Safety and Limits
Osprey enforces at two levels: limits checking (auto) and human approval (human interactive). If you adjust the safety settings update your agent with `osprey claude regen`. You can check if the artifacts are in sync by `osprey claude status`.
# Limits
Limits can be placed on element settings in `data/channel_limits.json`. This also can be used to designate certain channels as read only
